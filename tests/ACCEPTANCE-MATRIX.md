# Acceptance matrix

Матрица фиксирует проверяемые входы и ожидаемые результаты целевой архитектуры. Наличие спецификации, интерфейса, фикстуры или expected-failing теста не считается исполненной приёмкой. Для каждого модуля перед расчётом функционального покрытия согласуются denominator и независимые input/result scenarios; целевой порог — не менее 60% для каждого модуля. Statement coverage — отдельная метрика.

## Целевой Website/Content контракт

Pages имеют server-generated UUID и независимые snapshot trees в пределах `page_id`; snapshots и pages не содержат URL или route. System-wide model и Content records/publication общие для страниц, но разделены по locale: переводы — отдельные records с отдельными IDs и общей translation identity, а публикации и selections изолированы по locale. Публикация запускает durable rebuild fan-out по связанным `(route, locale)` targets; каждый Router target активируется отдельным CAS. При частичном отказе неуспешный target сохраняет прежнюю выдачу, успешные не откатываются, stale results отбрасываются, повторная попытка безопасна.

## Website scenario ledger

Независимые Website input/result scenarios и их стабильные `WEB-###` IDs находятся в [`qa/website-scenarios.json`](qa/website-scenarios.json). Этот ledger — единственный источник Website denominator: `covered` означает содержательную tagged acceptance-проверку, а `gap` и `blocked` остаются в denominator, но не в числителе; execution status учитывается отдельно. `blocked` требует точного prerequisite и не заменяется успешным fake-only или live-environment прогоном. `WEB-012` исполнен реальным integration-тестом `TestWebsiteFeatureImportAcceptance/WEB-012` (`tests/go/main/cmd/zubrium/website_feature_import_acceptance_test.go`) на disposable PostgreSQL/S3: идемпотентный replay, конфликт fingerprint, crash recovery и отказ invalid ZIP без partial ready version confirmed. `WEB-019` исполнен реальным integration-тестом `TestWebsiteMediaDerivativeAcceptance/WEB-019` (`tests/go/main/cmd/zubrium/website_media_derivative_acceptance_test.go`) на disposable PostgreSQL/S3 с Docker/Linux sandbox: pinned `x-media`, отказ client override, канонические `profile_digest`/`processor_version`, idempotency/restart, split/conflict, ≥2 renditions и готовность только после всех outputs, отсутствие partial output, сохранение field/original, MIME/size/checksum failures, immutable derivatives, groups/FileSet memberships, а также kernel-enforced seccomp/AppArmor/cgroups/network denial изнутри контейнера.

## Верификация

Каждый acceptance-сценарий проверяет предусловия, действие, ожидаемый ответ и состояние после выполнения. Browser/API checks не пишут в live API; реальная Website проверка использует отдельную disposable среду. Команды, результаты, пропуски и ограничения записываются в [QA report](../docs/QA_REPORT.md).
