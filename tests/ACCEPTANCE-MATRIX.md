# Acceptance matrix for the target architecture

This is a traceability list, not evidence of passing tests or a coverage percentage. Tests for the new product are under `tests/go` and use the repository Go overlay; frontend tests are under `tests/frontend`. Historical results in `docs/CORE-TEST-COVERAGE.md` and `docs/QA_REPORT.md` describe older code and do not prove this target architecture.

The agreed target is at least 60% of the acceptance input sets for each module. Each set needs a precondition, action, expected outcome, and relevant state assertions. A test of an interface or fake alone does not count as end-to-end behavior for an external boundary. Red tests document missing behavior but do not count as implemented coverage. Fix the denominator for each module before calculating a percentage; do not inflate it with trivial variations. No target-wide denominator or current percentage is approved yet.

The current implementation includes Core architecture, Coordinator, and a first Presentation API v2 scaffold. The Coordinator workflow boundary has dedicated PostgreSQL acceptance datasets for delayed availability, explicit and cross-workflow dependencies, restart recovery, result persistence, lease takeover/fencing, attempt exhaustion, retention, and store failures. Presentation handler, frontend API-client, and Router upload scenarios have been added but are still deferred and do not count as verified acceptance sets. Website branch-listing acceptance validates malformed addresses, CORS origins, snapshot IDs, revisions, timestamps, event records, duplicate branch IDs, and null collections. Dashboard/Settings tests cover group-based navigation and read-only branch display. One Router process per branch is now the deployment contract; branch selection and its listener are excluded from the shared Coordinator fingerprint, while other Router configuration remains fingerprinted. An explicit dev-fixtures profile provides synthetic read-only Website/Content/Forms responses and a UI warning; its build and tests remain deferred. Production runtime composition for Website, Content, Forms, remaining Admin screens, and per-module scenarios is open. The Router has no request-rate limiter and must stay behind an external proxy whenever public routes are exposed; proxy deployment and policy are owned by the deployer and are outside this repository. Each table-driven input remains a separate dataset; these additions do not establish a target-wide functional percentage. Site structure/design/model editors are not migrated yet. The test/build/browser sweep remains deferred until implementation work is complete.

17 November final verification: `make coverage` passed on fresh disposable PostgreSQL databases at 70.3% aggregate Go statement coverage; `make build build-full test vet` passed and the AST package-boundary check covered 20 local Go modules. The added delayed/restart/dependency/takeover/retention/exhaustion/store-outage cases and direct-layer/no-`internal` guard passed. The 70.3% statement metric does not establish the separate 60% target-functional acceptance metric. The target-wide denominator is still open; product-module workflows without implementations remain outside this Core/Coordinator pass, and interface-only contract tests do not count as functional coverage.
