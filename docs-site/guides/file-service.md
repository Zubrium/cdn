# Файловый HTTP API

Файловый API предназначен для серверных интеграций. Для каждого сервиса оператор задаёт имя, права и секретные ключи в `FILE_SERVICES`. Идентификатор владельца генерирует движок; секреты передаются через переменные окружения или secret files.

Все запросы идут к `/api/v2/files` с заголовком `Authorization: Bearer <service-key>`. Ключи имеют области доступа `upload`, `read`, `list`, `delete` и `link`. Владелец видит только свои объекты; администраторская медиатека и файлы интеграции отделены.

## Загрузка частями

1. `POST /uploads` — передайте имя, размер, SHA-256 и видимость `public` или `private`.
2. Разбейте файл на части заданного сервером размера.
3. Отправляйте каждую часть через `PUT /uploads/{id}/parts/{number}` с `X-Content-SHA256`.
4. При разрыве прочитайте `GET /uploads/{id}` и отправьте отсутствующие части.
5. Выполните `POST /uploads/{id}/commit`. Сервер проверит полноту, размер и итоговый SHA-256.

Лимиты, квоты, размер частей и TTL сессии явным образом задаёт оператор. В примере конфигурации лимит файла составляет 5 GiB; это не скрытый кодовый default.

## Прочитать файл или создать ссылку

- `GET /objects/{id}` возвращает метаданные.
- `GET` или `HEAD /objects/{id}/content` потоково читает содержимое.
- `POST /objects/{id}/links` создаёт ограниченную по времени ссылку с TTL не выше настроенного максимума.
- `GET /objects/{id}/references` показывает ссылки, известные движку.
- `DELETE /objects/{id}` удаляет объект; если на него ссылается сайт, нужны явное подтверждение и актуальная ревизия списка ссылок.

Подробный перечень методов и охранных правил генерируется в [справочнике HTTP API](../reference/api).
