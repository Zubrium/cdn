# Развёртывание и конфигурация

Оператор задаёт все рабочие значения в окружении или secret files. В репозитории есть [полный перечень переменных из `.env.example`](../reference/configuration).

## Запуск

1. Скопируйте `.env.example` в локальный конфигурационный файл.
2. Замените примеры на значения своей установки, задайте секреты вне репозитория.
3. Настройте PostgreSQL, S3-совместимое хранилище, главный HTTP listener и статические `BRANCHES`.
4. Убедитесь, что внешний gateway направляет домены и TLS к нужным портам веток.
5. Запустите Engine и проверьте `GET /health/live` и `GET /health/ready`.

Публичные порты, CORS и индексация принадлежат каждой ветке. Canonical-домен хранится в настройках сайта. Секреты нельзя задавать в открытом example-файле.

## Переименование ветки или сервиса

Используйте только с остановленным Engine и правильным `DATABASE_URL`:

```sh
docker compose stop server
docker compose run --rm --no-deps server rename-branch OLD_NAME NEW_NAME
# обновить имя в BRANCHES и перезапустить
docker compose start server
```

Для файлового сервиса используйте `rename-service` и обновите `FILE_SERVICES`. Команды сохраняют автоматически созданные идентификаторы. Не запускайте переименование на рабочей базе без резервного копирования и планового окна.

Полные формы и список поддерживаемых операторских команд генерируются в [справочнике CLI](../reference/cli).

## Резервное копирование

Резервируйте PostgreSQL и объектное хранилище согласованно. Sitepack предназначен для переноса состояния сайта, но не переносит пользователей, заявки и административные токены.
