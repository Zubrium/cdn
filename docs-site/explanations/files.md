# Файлы и медиа

Engine использует один реестр неизменяемых объектов с типом владельца. Один владелец принадлежит админской медиатеке; у каждой серверной интеграции свой владелец. Повторная загрузка тех же байтов не превращает объекты разных владельцев в общую публичную запись.

```mermaid
flowchart LR
  Admin[Администратор] --> Media[/media: загрузка и выбор]
  Service[Внешний сервис] -->|Bearer с правами| FileAPI[/api/v2/files]
  Media --> OwnerA[Admin owner]
  FileAPI --> OwnerS[Service owner]
  OwnerA --> Object[(Private object storage)]
  OwnerS --> Object
  Object -->|public endpoint / signed link| Consumer[Сайт или интеграция]
  Ref[Ссылка в контенте / теме / размещении] --> OwnerA
```

Загрузка файлов выполняется частями в дисковую временную область; commit подтверждает полный размер и SHA-256. Идентификатор неизменяем: замена байтов создаёт новый объект. Ссылки интеграции имеют ограниченный TTL, а private objects не выдаются через публичные кэши.

Перед удалением Engine показывает известные ссылки из своего состояния и требует подтвердить актуальную ревизию списка. Ссылки, хранящиеся вне Engine, система обнаружить не может.
