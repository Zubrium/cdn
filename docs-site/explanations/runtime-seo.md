# Публичный runtime и SEO

Публичная ветка выбирает снапшот по своему назначению, разрешает путь страницы, собирает общие метаданные и выдаёт размещения закреплённых фич. Engine формирует `robots.txt` и `sitemap.xml` с учётом политики индексации ветки.

## Без JavaScript и с JavaScript

Новые сборки используют статические browser ABI:

- `static-html-v1` возвращает разрешённый HTML-фрагмент, который виден до запуска клиентского кода;
- `static-module-v1` загружает ESM entrypoint и CSS, локальные относительно сборки;
- legacy React ABI остаётся читаемым на период миграции.

Если включён пререндер, sandboxed Chromium загружает страницу и сохраняет финальный HTML после готовности фич и публичных GET-запросов. Безопасные лимиты worker задаются конфигурацией. Ошибка или тайм-аут не считаются успешно сгенерированным результатом.

## SEO-политика

`indexable` задаётся для ветки при запуске. Неиндексируемая ветка получает закрывающие правила в `robots.txt`; индексируемая ветка получает карту сайта. Metadata и canonical задаются сайтом в снапшоте, а внешняя связь домена с портом настраивается в gateway.

Публикация контента, смена назначения и изменение страницы должны давать согласованный cache identity. SEO и пререндер улучшают доступность содержимого для crawler, но не гарантируют позицию или рейтинг в поиске.
