# Активный план Website Engine

## Состояние

Внешний HTTP API использует пути `/api/...` без версионного префикса. OpenAPI остаётся версии 3.1; `info.version` — метаданные документа. Внутренние версии данных, схем, feature builds, component contracts, snapshots и миграций сохраняются.

Композиция `main` собирает компоненты профиля через запечатанный runtime bus со статическим allowlist. Record store Website, Content, Forms, Router, Loader, Archive и Media переведён на typed `pkg/contracts` operations с composition-bound owner scope; результат проверен в `output/record-databus-20261123-b/`. Durable Coordinator переведён с `WorkerCatalog`/`WorkerRef` на generic operation/task-class contracts. Component descriptors теперь лежат в neutral `pkg/contracts`, собираются `main`, а Core registry хранит только opaque owner IDs; Core identity/files API использует нейтральные capability names. Файловые операции Prerender, Archive, Media и Router delivery используют `core.files.*` DataBus clients со scoped stream bytes. Router Routes identity/group authorization также переведены на typed `core.access.*` операции с привязкой разрешённых групп к profile descriptor. Identity/session/authorization/staging и другие File API операции всё ещё доступны части модулей напрямую, без DataBus. Durable Website build подключён в full-профиле: root `engine.website/build-page/v1` эмитит `worker.prerender/render-page/v1`; prerender sandbox и Router activation остаются fail-closed/неподключёнными. Manifest-pinned media derivative подключён в full-профиле через изолированный runner. Boundary gate остаётся красным: 33 прямых Core import в 32 файлах `engines/` и `presentation/`; `workers/archive`, `workers/media`, Content repository, Router Routes и Router delivery очищены. Миграция остальных вызовов и acceptance fixtures остаётся активной задачей.

Integration-прогон на disposable PostgreSQL/S3 прошёл: `CORE-001`, `WEB-018`, `WEB-019`, `WEB-020`, `WEB-021` и `WEB-022` исполнены реально, а не через `t.Skip`. Browser QA Admin выполнен в отдельном checkout с изолированным full-профилем, disposable PostgreSQL и `moto`; проверены 12 экранов, responsive 360–1920 px, темы, клавиатурный фокус, диалоги и публичный listener. Найденные дефекты — пустой фильтр `ListSnapshots`, глобальная Core revision в Website-декодерах, пустой metadata новой страницы, mobile overflow и SSE same-origin — исправлены с regression-тестами. Ограничения и точные команды зафиксированы в [QA report](QA_REPORT.md); оставшиеся blocked-сценарии не трактуются как pass.

Контракт Forms переведён на глобальные схемы без `snapshot_id`: метаданные — только `key + fields`, ключ глобально уникален, submissions фильтруются по обязательному `form_id` и необязательному `key`, Router-привязки остаются pinned на версию схемы. Admin получил вложенные страницы `/admin/forms`, `/admin/forms/new` и `/admin/forms/:formId`; публикация из UI использует редактируемый base path `/forms/<key>` и включает upload-операцию только при `file`-полях. Site editor поддерживает route-аргумент `format: "route"`/`source: "route"` с предупреждением, не блокирующим сохранение. Текущие проверки и известные ограничения (в том числе 503 feature catalog) зафиксированы в [QA report](QA_REPORT.md).

Целевой контракт описан в модульных спецификациях и OpenAPI. Ни этот план, ни наличие интерфейсов/заглушек не доказывают готовность реализации. Чекбоксы закрываются только после выполнения критериев и записи результатов в [QA report](QA_REPORT.md).

## Порядок проверки

Сначала завершается применимая реализация и документация. Затем выполняются `make test`, `make vet`, `make build`, `make build-full` и из `frontend/` — `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`. Интеграционные проверки выполняются только на одноразовых ресурсах с точным учётом созданных идентификаторов и безопасной очисткой.
