## Публичная выдача CSS

`GET /api/v2/site-themes/snapshots/{snapshotId}` доступен без авторизации только для темы, назначенной текущей публичной ветке. ID ветки берётся из серверного контекста listener-а; клиент не может выбрать ветку через query, заголовок или payload. Проверка enabled-ветки, `active_snapshot_id` и чтение payload выполняются одним запросом к БД: отсутствующая, отключённая ветка, отсутствие назначения или несовпадение ID возвращают 404 без CSS и без кеширования. Успешный ответ сохраняет текущую политику обязательной revalidation. Preview остаётся отдельным route с непрозрачным краткоживущим token и не использует публичное назначение ветки.

Acceptance: content-role пользователь может увидеть ID неназначенного снапшота, но анонимный запрос его CSS получает 404; другая ветка не получает CSS снапшота, назначенного соседней ветке; назначение снапшота разрешает CSS только на этой ветке, а последующая смена назначения снова запрещает старый ID. Preview-token route продолжает работать независимо.

Группа содержит UUID и название. Базовый токен содержит UUID, название, groupId, kind и структурированное значение. UUID создаёт форма, сервер проверяет уникальность и тип. В админке нет ручного ввода ID или CSS-имени. Список видов: `color`, `length`, `number`, `font`, `shadow`. Цвет — HEX и непрозрачность 0…100; длина — конечное число и разрешённая единица; шрифт — системное семейство либо зарегистрированное семейство WOFF2; тень — числовые x/y/blur/spread, цвет и inset. Произвольные CSS-функции, URL и выражения не принимаются.

Манифест фичи содержит `designTokens`: key, label, group, kind, default. Разработчик читает CSS custom property `--feature-<featureKey>-<key>`. Значения определений проверяются при импорте ZIP. Это расширение декларативного манифеста, без изменения ABI кода. Админка получает только определения закреплённых builds выбранного снапшота. Настройки фичи общие для всех её placements.

`featureValues` индексируется `<featureKey>/<tokenKey>`. Значение содержит literal либо `baseTokenId`. Ссылка разрешена только на базовый токен того же kind; базовые токены не ссылаются на другие токены, поэтому циклы невозможны. Отсутствующие определения и несовместимые ссылки отклоняются. Удаление используемого токена предварительно требует убрать ссылки. Сброс feature value возвращает default из манифеста.

При изменении состава фич или их версий дочерний снапшот сохраняет все ранее заданные значения. Значения удалённых токенов и значения токенов, чей тип изменился, переносятся в `legacyFeatureValues` с подписью, фичей, исходной версией и типом; для размеров экрана это поле хранится внутри соответствующего порога. Они не применяются в CSS и не отображаются среди активных настроек отсутствующей фичи. Интерфейс показывает список сохранённых неиспользуемых настроек и причину. Если позже снова выбран совместимый токен и у него ещё нет текущего значения, последняя совместимая сохранённая настройка восстанавливается; остальные исторические значения остаются сохранёнными. При невозможности восстановить ссылку на удалённый базовый токен или шрифт значение остаётся в истории и не блокирует создание снапшота. Явное удаление базового токена не удаляет ссылки из истории, но блокируется при использовании активными токенами или переопределениями. Эти данные принадлежат потомку; родитель не изменяется.

CSS-имена для каждой пары фича/токен должны быть уникальны после формирования `--feature-<featureKey>-<key>`. Две разные пары, дающие одинаковое имя, отклоняются при проверке состава снапшота с диагностикой; это предотвращает случайное переопределение чужой фичи. Внутри снапшота названия групп уникальны без учёта регистра и пробелов по краям; названия базовых токенов уникальны в своей группе. Пустые и повторные названия показываются в интерфейсе до запроса и повторно проверяются сервером.

Breakpoint содержит UUID, название, `minWidthPx`, `baseValues`, `featureValues`. Ширины — неотрицательные целые числа без дубликатов. CSS формируется в порядке возрастания min-width; наибольший подходящий порог побеждает, отсутствующие значения наследуются. Ссылка на базовый токен использует CSS var и автоматически учитывает его переопределение. Удаление порога с переопределениями требует подтверждения.

## Сравнение с родительским снапшотом

Редактор потомка читает дизайн непосредственного родителя тем же GET. Сравниваются текущие значения формы, включая несохранённый ввод, с сохранённой темой родителя. Базовый токен сопоставляется по ID, токен фичи — по ключам фичи и токена. Для токена, которого у родителя не было, отображается отметка «Новый относительно родителя». Удалённые токены остаются вне активных настроек потомка.

В режиме базовых значений сравнение идёт без порогов. На выбранной ширине каждый снапшот разрешает значения по собственным порогам, включая наследование и ссылки на собственные базовые токены. Для токена фичи учитываются значение и источник: значение закреплённой сборки, заданное значение или ссылка на конкретный базовый токен. При отличии редактор показывает прежнее значение и источник токена фичи. Значения выводятся без CSS и внутренних идентификаторов. Совпадающие токены и корневой снапшот не получают отметок.

Сравнение доступно для графических тем. Если родитель не загрузился, пользователь может повторить запрос и продолжить редактирование. Сравнение не сохраняет тему и не создаёт снапшот.

## API и публичная тема

GET `/api/v2/admin/site/snapshots/{id}/design-system` возвращает snapshot, designSystem, featureTokens. POST принимает name и designSystem, валидирует по pinned builds и создаёт потомка. Доступ: менеджер сайта. Устаревший снапшот остаётся самостоятельным источником; его структура неизменяема, поэтому обновление контента не создаёт конфликта дизайн-конфигурации. Ошибка/отмена не создаёт потомка; локальный ввод остаётся доступным, уход предупреждает о потере изменений.

Runtime использует `DesignSystemCSSForBuilds`: проверяет значения и имена, сериализует только разрешённые CSS конструкции, добавляет WOFF2 face по file ID. Никаких приватных URL и произвольных селекторов. Логотип и шрифты являются публичными ресурсами сайта: при сохранении снапшота сервер проверяет доступность, visibility=public и соответствующий MIME каждого использования, даже если один файл выбран для нескольких назначений. Закрытые файлы остаются доступными через файловый сервис, но не допускаются как публичный логотип или шрифт.

В разделе «Шрифты и бренд» пользователь выбирает ранее загруженный публичный WOFF2 или логотип из медиатеки. Диалоги выбора ведут в `/media` для загрузки. Редактор показывает образец текста выбранным начертанием и сообщает об ошибке загрузки образца. Браузер загружает образец через публичный `/media/{id}`. Шрифт образца удаляется из набора `document.fonts` при смене файла, начертания или выходе из раздела. Общая кнопка «Сохранить» создаёт дочерний снапшот с ID выбранных ресурсов. После отдельного назначения потомка ветке публичная тема запрашивает WOFF2 по `/api/v2/system-assets/{id}`, а публичная композиция передаёт URL логотипа фичам.

Проверки: generic пустая тема; только pinned definitions; одинаковые значения всех placements; наследование и независимый потомок; несовместимая/отсутствующая ссылка; коллизии ID/key; invalid numbers/colors/units/URLs; порядок порогов; использование переопределённого base через feature reference; создание группы/токена в UI; reset/delete/unsaved/error; desktop/mobile/light/dark/keyboard; Vitasil ZIP import и runtime CSS.

API для `formatVersion=2` всегда сериализует обязательные коллекции и словари, даже если они пустые: `groups`, `baseTokens`, `breakpoints`, `fonts` — массивы; `featureValues` — объект. Клиентские типы полагаются на эту форму. Не опускать её через `omitempty`.
