# Заявки и ветки

Источник: [TODO](TODO-admin-snapshots-content-files.md). Заявки не входят в снапшот и не копируются при создании потомка. Публичный listener назначает branch ID через контекст; клиент не может подменить ветку параметром тела заявки. Схема отправки берётся из manifest закреплённого build активного снапшота и проверяется строго, включая required.

Мягкое удаление оставляет tombstone для хранения статуса удаления, но скрывает запись из списка, CSV-экспорта и прямого detail GET для всех ролей. Знание ID не даёт повторно прочитать данные после удаления; отдельного API просмотра удалённых заявок нет.

Отправка захватывает общую транзакционную блокировку файловых ссылок, затем разделяемую блокировку строки ветки, считывает текущий закреплённый манифест в той же транзакции и проверяет схему и media-ссылки до сохранения заявки. Одновременное переназначение ветки сериализуется относительно отправки; удаление файла либо очищает уже сохранённую заявку, либо завершится раньше, после чего отправка не примет отсутствующий файл. Файловые ссылки в заявках не обязаны быть публичными, но должны указывать на существующие готовые объекты. Отказ оставляет заявку несохранённой. На пуле из одного соединения обработка не должна получать второе соединение изнутри транзакции.

Физическое поле `form_submissions.environment` хранит branch UUID. API добавляет `branchId`; прежнее `environment` временно сохраняется как алиас для исторических тестов. Новый фильтр `branchId` принимает UUID, пустое значение означает все ветки. Перед сравнением UUID нормализуются, поэтому регистр hex-символов и согласованная пара `branchId`/`environment` не меняют результат. Одновременно заданные разные branchId/environment отклоняются. Отсутствие ветки в конфигурации не удаляет заявки или их схему.

Список и CSV используют один набор фильтров: форма, ветка, статус, период создания [from,to), строка поиска, поле поиска, включение архива, сортировка по дате создания asc/desc. Одинаковое время разрешается по ID; курсор содержит timestamp и ID, новые записи не смещают следующие страницы. Изменение фильтра в UI начинает выдачу заново. Период с to <= from, неверный статус/ID/сортировка/курсор возвращает понятную ошибку. CSV применяет те же условия и защищает значения от исполнения формул; branchId и formKey включены явно. Лимит строк экспорта задаётся оператором (`SUBMISSION_EXPORT_MAX_ROWS`); если результат превышает его, API возвращает 413 с `export_limit_exceeded`, не создавая неполный CSV.

Выбор «Все формы» запрашивает общий список, а не пустой экран. `GET /api/v1/admin/submissions` и `/api/v1/admin/submissions/export` применяют те же права и фильтры ко всем формам; cursor используется только для постраничного списка, а CSV содержит полный подходящий набор в пределах настроенного лимита. Существующие маршруты конкретной формы сохраняются. Доступные поля поиска объединяют схемы заявок и активных форм выбранной ветки, а при выборе всех веток — всех настроенных веток. Пустая таблица остаётся корректным результатом, в том числе при отсутствии форм. При смене формы или ветки ранее выбранное поле сбрасывается, если оно может не существовать в новом наборе схем. Кнопка сброса появляется при любом отклонении от начальных параметров, включая выбранную форму и сортировку, и возвращает сортировку к дате по убыванию.

Поля поиска и CSV — объединение схем текущих build во всех настроенных ветках и схем реально сохранённых заявок выбранной формы/ветки. Удаление/замена фичи, отключение ветки или изменение manifest не делает старые поля недоступными. Произвольное имя поля не превращается в SQL; используются параметры. Поиск по всем полям не должен молча обрезать список до первых десяти полей. `%` и `_` в поиске — обычные символы пользовательской строки.

Роли и маршруты остаются прежними: сервер проверяет доступ к чтению/экспорту/статусу/архиву/удалению. Админка отображает названия настроенных веток вместо dev/prod. GET `/api/v1/admin/submission-branches` доступен той же роли user и возвращает только id/name/enabled настроенных веток и отключённых веток с сохранёнными заявками. Управленческий branches API остаётся manager-only. Для исторической заявки без доступного названия показывается «Недоступная ветка», без ручного ввода ID.

Проверки: две ветки/одна форма с разными версиями schema; фильтры независимо и совместно; дата/статус/поиск по старому полю; стабильная пагинация при одинаковом created_at и новой отправке; CSV содержит ту же последовательность, branchId и безопасные ячейки; строгая отправка отсутствующего required; отключение ветки не теряет историю; отказ ролям; UI loading/empty/error и фильтры desktop/mobile.

## Проверка реальной формы Vitasil, 6 ноября 2026

В отдельной disposable-среде через админку добавлена `form@1.0.4` в дочерний снапшот #5; его назначение подтверждено только для `vitasil preview`. `vitasil public` осталась без назначения. В редакторе заполнены тексты формы, явная публикация обновила форму в том же снапшоте. После отдельного изменения чернового заголовка и перезагрузки редактора значение сохранилось, тогда как публичная страница продолжала показывать опубликованный заголовок; черновик возвращён к опубликованному значению.

Публичная форма показала тексты из манифеста/контента, успешно приняла три тестовые заявки и отобразила подтверждение. В админке проверены выдача по форме и ветке, фильтрация новых/обрабатываемых заявок, поиск по имени, диапазон `2026-11-06`—`2026-11-06`, сортировка по возрастанию, пустой результат, изменение статуса и CSV. Экспорт содержал те же три записи в запрошенном порядке с `branchId` и ожидаемыми полями. Проверка проводилась в браузере Playwright CLI на API `127.0.0.1:38410` и публичной ветке `127.0.0.1:38411`; рабочий сервис Vitasil не использовался.

Ограничения: передачу пустой формы нажали, но browser assertion состояния validity/ответа API отдельно не снимали; строгая серверная проверка обязательных полей прошла в `TestExternalVitasilFormKeepsSubmissionFieldsRequired` из `go test -count=1 ./...`. Не проверялись права нескольких ролей, архивирование, ошибки сети/загрузки, пагинация на нескольких страницах, независимое разделение одной формы по двум назначенным веткам, а также полная мобильная/accessibility-матрица. Проверенный до фикса `404` браузерного fallback `/favicon.ico` устранён: серверная HTML-оболочка теперь сразу указывает на доступный embedded `/favicon.svg`, ещё до гидратации; fallback покрыт unit-тестом.

## Полный UI-прогон заявок, 7 ноября 2026

Добавлен отдельный `TestSubmissionsBrowserAcceptanceWithVitasilForm`; он требует `TEST_DATABASE_URL` с loopback host и именем базы `website_engine_submissions_ui_*`, актуальные браузерные переменные Playwright и каталог ZIP-фич. Прогон выполнен на свежей disposable PostgreSQL `website_engine_submissions_ui_20261106_01` и `form-1.0.9.zip` из `/Users/docup/Projects/vitasil/frontend/dist/feature-builds`. Тестовый object store — отдельный in-memory `fakeStore`; рабочие API, БД и storage Vitasil не использовались.

В тесте созданы две независимые назначенные ветки и 43 заявки (40 development, 3 production), одна запись перенесена на предыдущую UTC-дату, одна архивирована. Chromium проверил список всех форм и 3 страницы с размерами 20+20+2, выбор ветки и формы, текстовый поиск по полю `name`, диапазон дат, сортировку asc, статус и их совместное применение, фильтр архивных записей, CSV по branch filter и подтверждённое архивирование. Задержанный ответ PATCH подтвердил disabled/saving state; поддельные ответы 503 проверили error и ручной retry, а поиск без совпадений — empty/reset state. Для admin, moderator и user подтверждены аутентификация ожидаемой роли, чтение и CSV; удаление показывается только admin. На ширине 390 px проверены карточный список и доступный поиск, таблица скрывается. Подписи фильтров доступны по label, статусный список открывается и выбирается с клавиатуры. Удаление в тесте не выполнялось.

Проверки прошли:

- `go test -count=1 -v ./cmd/integration -run '^TestSubmissionsBrowserAcceptanceWithVitasilForm$'` на disposable PostgreSQL с актуальным Vitasil ZIP и Chromium.
- `go test -count=1 -v ./cmd/integration -run '^(TestBranchSubmissionFiltersHistoryAndExport|TestAllFormsListSearchAndExportShareFilters|TestExternalVitasilFormKeepsSubmissionFieldsRequired)$'` на той же disposable PostgreSQL.
- `go test -race -count=1 ./features/forms ./presentation/http/handlers/forms`.
- `go vet ./features/forms ./presentation/http/handlers/forms`.
- Frontend Node 20: `pnpm typecheck`, `pnpm lint`, `pnpm test` (13 файлов, 60 тестов) и `pnpm build`.

UI корректировка: убрана вторая одноимённая кнопка «Сбросить фильтры» из пустого состояния; единственный сброс находится рядом с фильтрами и остаётся доступен при пустой выдаче. Предыдущая запись о незакрытой полной браузерной матрице заменяется этим прогоном для UI списка заявок. Ограничения: ошибка API моделируется перехватом 503 в браузере, а не отказом реального сервера; тест не является формальной WCAG/скринридерной оценкой и не повторяет публичное заполнение формы — оно проверяется отдельно. Browser acceptance выполнялся только на изолированном `httptest` API с disposable данными.
